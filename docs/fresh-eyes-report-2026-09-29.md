## 0. What kern is (in its own words)

- README tagline: *"The local, deterministic code-intelligence engine for AI
  agents"* — "Index · Graph · Guard · Audit · Optimize — One self-contained CLI
  binary. Local-first, no telemetry." (`README.md:5-6`)
- `docs/architecture.md`: *"a local-first, zero-network context and agent
  orchestration engine built in Go … pre-indexed symbol graphs, AST analysis,
  security and architecture firewall enforcement (Gates G0–G39), and a 7-role
  specialist agent squad for AI coding assistants"* (`docs/architecture.md:2`)
- README positions it against "The AI Agent Context Crisis": context bloat,
  hallucinated dependencies, slow iteration, privacy leaks; claims surgical AST
  slices of 500–2,500 tokens vs 50–150k for naive agents, <10 ms search, and
  45–80% token savings (`README.md:41-71`; the latency/token figures are at
  `README.md:70-71`).
- Feature summary: "17 Indexed Languages · 74 Frameworks Recognized ·
  Phase-aware MCP Routing (11 high-level tools by default, 139 in full mode) ·
  100% Local" (`README.md:35`).

**Scale:** 181,207 non-test Go LOC across the repo (`find … -name '*.go'
! -name '*_test.go' | xargs wc -l`); `internal/` alone is 160,960 LOC in 109
top-level packages.

`kern --all` renders the full grouped catalog — 25 categories (meta 8, wiring 10,

### Command table (source)
- `commandTable` is a single `map[string]commandEntry` (`dispatch_table.go:60`):
  **216 entries**, of which **16 are formally `alias:true`** (snake_case MCP-mirror
  spellings like `doc_fetch`, `pre_edit`, `semantic_merge` — hidden from help and
  the banner count, backward-compatible) and **200 are non-alias** — exactly what
  the banner advertises (`commandCount` defined `main.go:37`, banner call
  `main.go:80`). A further ~20 spellings
  act as aliases without the flag (`what-if`/`simulate`→`impact`,
  `security`→`sec`, `ask`→`meta`, `web`/`ui`→`serve`, `autonomy`→`loop`…).
- **One flag parser for everything:** `parseFlags` (`flags.go:286`) — documented
  contract (`flags.go:217-256`): trailing value-less flags accept-and-default;
  `--flag=value` and `--flag value` both work; bools `--flag/--flag=true/
  --flag=false`; unknown flags fail with `"unknown flag: X"` (usage, exit 2);
  parsing does NOT stop at the first positional. All 29 former stdlib `flag.FlagSet`
  instances route through it.
- **Exit codes** (`cmd_exitcode.go:52-63`, `helpers.go:679-710`): `0` ok/reported
  outcome; `1` runtime error (also FAIL verify, no-match search); `2` usage
  (`fatalUsage`); `3` decided-state/policy (`fatalPolicy` — already-decided
  approval, missing receipt, invalid Blueprint config, changed files with risk,
  denied context authorization, error-severity security findings). Implemented via
  an `exitError` sentinel that `main()` recovers into the process exit code
  (`main.go:233-264`).
- **Dispatch flow:** `main.go:209` → `resolveCommandAndFlags` (`dispatch.go:13`;
  pre-dispatch exits for no-command, `--all`, `help <topic>`, `--help`) →
  `dispatchCommand` (`dispatch.go:204`; table lookup + nearest-match suggestion)
  → `os.Exit(code)`.
- **`--root` semantics:** `resolveRoot` (`helpers.go:806`) — `--root` flag, else
  first positional, else `.`.
- **`kern update`** is *"the one kern command that intentionally touches the
  network"* — it delegates to install.sh (`cmd_update.go:91`) with a fail-closed
  local guard that refuses unverifiable builds (`cmd_update.go:179`);
  `--force`/`--pin` are the only overrides.

## 4. AGENT lens — what a fresh AI agent gets after `kern setup`

### AGENTS.md (universal instruction file)
- 111 lines, identical to the embedded asset `internal/setup/assets/AGENTS.md`,
  bracketed by `<!-- kern-instruction: managed by kern setup … -->` markers.
- **Kern-first policy, ENFORCED & AUTONOMOUS** (`AGENTS.md:31`): *"You MUST
  call a `kern_*` tool before any built-in `read`, `grep`, `glob`, or `bash`"*;
  on hook-supporting hosts the built-in is BLOCKED; on opencode it is routed.
- 9-step decision procedure (`AGENTS.md:33-73`): `kern_compact_file` before
  `read`; `kern_project_map` not `glob`; `kern_ast_search`/`kern_doc_search` not
  `grep`; `kern_validate` not build; `kern_exec` not `bash` (with the macOS
  fail-closed note).
- Tool-routing table (`AGENTS.md:75`); session-start mandate: call
  `kern_onboard`/`kern_buddy` first, then `kern_memory_recall` (`AGENTS.md:84`).
- Tool count claimed: "139" (`AGENTS.md:11,26,102`) — confirmed (see §5).

### .mcp.json (project)
```json
{"mcpServers":{"kern":{"command":"kern-mcp","args":[],"env":{}}}}
```
Deliberately **no `KERN_ALLOW_EXEC`** — exec is opt-in per host so a committed
config can't silently enable arbitrary command execution; `governance.CheckExec`
fails closed without it (`setup_opencode.go:12-18`).

### The opencode plugin (`kern.ts`, 3,118 lines)
Single exported `Plugin` (`kern.ts:359`). Hooks:
- **`config`** — injects `"kern_*": "allow"` into every subagent's `permission`
  (injection at `kern.ts:3010`), overriding their `"*": "deny"` catch-all so
  built-in agents (explore/fixer/…) see kern tools (`kern.ts:2996-3017`).
- **`tool.execute.after`** — auto-compresses oversized bash/read/grep output
  through `kern log` (>4,000 chars threshold; exempts `full=true` reads and
  `raw=true` calls) and records edits + command failures into project memory
  (`kern.ts:3018`).
- **`chat.message`** — rate-limited/deduped capture of substantive prompts into
  project memory (`kern.ts:3062-3087`).
- **`experimental.chat.system.transform`** — silent context-envelope injection
  into the system prompt (`kern.ts:3101-3118`).
- **Shadow tools** (opencode has no `context.tool`): `read`→`kern compact`
  (`kern.ts:2845`), `grep`→`kern ast`/`kern docs` (`:2900`), `bash`→`kern build`
  (`:2946`) — never raw-bypasses a governance denial; ~110 `kern_*` tools
  advertised with phase classification (`TOOL_PHASES`, `kern.ts:187-315`);
  `DEFAULT_TOOLS` = 11 (`:317-335`).
- Bypass knobs: `KERN_BYPASS=1` / `KERN_ENFORCE=0` / `KERN_SILENT=1`.

### kern-guard.sh — the PreToolUse guard
68 lines, embedded at `internal/setup/assets/hooks/kern-guard.sh`, installed to
`~/.kern/hooks/kern-guard.sh`. Reads a JSON payload on stdin (`.tool_name` /
`.tool` / Antigravity's `.toolCall.name`); **exit 0 = allow, exit 2 = block**
with the reason returned to the agent. Redirects:
`read|read_file|view_file` → `kern_compact_file`/`kern_context`; `grep|grep_file`
→ `kern_ast_search`/`kern_doc_search`; `glob|list` → `kern_project_map`;
`bash|run_shell|shell|run_command` → `kern_validate`/`kern_exec`.

## 5. MCP lens — what this MCP exposes

### Transport
- **stdio** (default): `cmd/kern-mcp/main.go:58`; SIGINT/SIGTERM cancel in-flight
  tools, release locks, drain ≤5 s (`internal/mcp/stdio.go:8`,
  `transport/transport.go:41`).
- **HTTP** (opt-in `-http ADDR`): Streamable-HTTP JSON-RPC to `/mcp`; `:8080`,
  `unix:/path`, or `auto`/`uds` sentinels (0600 unix socket in 0700 temp dir);
  loopback TCP only when unix unavailable or `KERN_MCP_TRANSPORT=tcp`; optional
  TLS (`-tls-cert`/`-tls-key` or `KERN_MCP_TLS_*`, loopback-only + Origin check).

### Tool catalog — 139 tools
Single source of truth: `internal/mcp/catalog/tools.go` (`var All = []Tool{…}`).
Count verified three independent ways: 139 catalog entries, 139 dispatch entries,
and live `kern mcp tools` output: *"kern MCP catalog: 139 tools (default MCP
surface advertises 11; `KERN_MCP_FULL=1` exposes all; `kern_meta` routes to
everything)"* — which also settles the 139-vs-140 discrepancy (AGENTS.md says
139; the embedded `global-rules.md` asset still says 140 — stale).

Each Tool carries `Phase` (explore/plan/edit/verify/cross), `RiskLevel`
(low→critical), `Category`, `SchemaVersion`, `Cacheable`, `Slow`
(`catalog/catalog.go:18-57`). **23 families** (`catalog.go:79-101`): analyze,
agent, arch, ast, context, doc, edit, evidence, exec, framework, graph,
governance, incident, lock, memory, meta, mcpbridge, optimize, org, project,
review, task, verify. Representative members: `kern_search/explore/graph/probe/
near/why/path/dead/cycles/larges/churn/communities/arch/hubs`, `kern_context/
compact_file/fit_context/context_budget/context_envelope/plan_context`,
`kern_impact/what_if/analyze/plan/execute/verify/run/workflow`, `kern_meta`
(router), `kern_authorize_context`, `kern_review`, `kern_optimize_prompt/log/
stats`, `kern_exec/sandbox/validate/heal`, `kern_agent_*`, `kern_doc_search/
index/fetch`, `kern_memory_add/list/recall/ranked`, `kern_org_*` (8),
`kern_mcp_call`, `kern_usage_guide/buddy`.

### Dispatch & governance
- **Data-table dispatch, not a switch** — *"a data table replaces control-flow
  cases"* (`dispatch.go:2-3`): `dispatchTable map[string]dispatchFunc`
  (`dispatch.go:38`), all handlers are `simple((*Server).handleX)` except
  `kern_sandbox`/`kern_heal` (take the call id) (`dispatch.go:26-33`).
  `dispatchTool` (`:189`) runs **RBAC** (`rbac.CheckAgentTool`, `dispatch.go:
  199`) before the handler — direct `tools/call`, `kern_meta` sub-routing, and
  `CallTool` all pass the same gate. Public callers: `CallTool` (trusted
  loopback, `:217`) and `CallToolGoverned` (full governed path incl. pre-tool
  hook, `:237`).
- **Root confinement, 4 layers** (`server.go` + `server_paths.go`):
  1. `withinRoot` (`server.go:1298`) — cleans, symlink-resolves both root and
     candidate, resolves nearest existing ancestor, rejects escapes;
  2. `rootedPath` (`:1086`);
  3. `checkRootArg` (`server_paths.go:115`) — rejects any path-typed argument
     (`root`/`dir`/`file`/`output`/`disk_path`/`*_file`) resolving outside
     workspace roots (`checkWithinWorkspace`, `server_paths.go:138`; "target"
     deliberately NOT confined);
  4. `validateRoot` (`server.go:1353`) — rejects filesystem roots / non-dirs.
  Plus `confinementGate` (`server.go:484`): the **`KERN_MCP_ROOTS` gate,
  default-on** (`server.go:413-416`), applied per `tools/call` as a pre-tool-use
  hook (`:950-967`); `KERN_MCP_NO_CONFINE=1` opts out. Default roots =
  `defaultWorkspaceRoots()` (`server_paths.go:77`): `KERN_MCP_ROOTS`/`KERN_ROOTS`/
  `mcp.roots` env, else server cwd. Full per-call pipeline: `precheckTool`
  (`toolpolicy.go:327` — KERN_TOOLS allowlist → `checkRootArg` → `validateRoot` →
  safety budget) then `runTool` (`server.go:1100` — arg coercion, response cache,
  audit-chain append, metrics).
- **`kern_run`** → `highlevel.Run` (`internal/mcp/highlevel/highlevel.go:543`):
  builds a task service, runs an intent through the pipeline, reports task id /
  workflow / intent / risk+approval state / capabilities / tools / agents / next
  / precheck (`:556-575`). **`kern_workflow`** runs the intent through the agent
  team with an exit gate + resume (`:582-619`). **`kern_meta`** → `meta.Handle`
  (`meta/meta.go:243`): deterministic keyword classifier over `metaRoutedTools`
  (`meta/meta.go:51`) + dependency-free token-overlap cosine semantic fallback
  (`meta/semantic.go:8,87` → `kern_search`).
- **`mcpclient`** (`internal/mcpclient/client.go:1-9`): minimal stdlib-only MCP
  client — `Dial`/`ListTools`/`CallTool` (`client.go:341/362/392`), stdio /
  streamable-http / unix, tools-only, names `mcp__<server>__<tool>` (SHA-256
  suffix on lossy normalization), protocol `2025-03-26`, config
  `.kern/mcp-servers.json`; exposed to agents via `kern_mcp_call`.

## 6. Server & web surfaces (help block 4, expanded)

### `kern serve` / `kern web` (`cmd/kern/cmd_serve.go`)
- Default `127.0.0.1:8090`; flags `--root` (`.`), `--addr`, `--enterprise`,
  `--project NAME=PATH` (`serveUsage`, `:53-78`).
- **Fail-closed bind guard** (`:142-146`): binding a non-loopback addr without
  `KERN_AUTH_TOKEN` is refused — *"unauthenticated RCE surface"*;
  `isLoopbackAddr` treats parse failure as non-loopback.
- Two modes (`buildServeHandler`, `:185-205`): single-project → `web.New(root)`;
  enterprise → `enterprise.New()` + `SetAppFactory(web.New)` + `--project` pairs.
- The MCP factory is injected in `init()` (`:34-52`): `web.SetToolServerFactory(
  func(root string) web.ToolServer { return mcp.NewServerForRoot(...) })` — breaks
  the `mcp → org → enterprise → web` import cycle (web cannot import mcp).

### Third binary `cmd/kern-server/main.go`
- Standalone **stdlib-only** HTTP server: digital-twin data as JSON + minimal
  server-rendered HTML dashboard ("No external dependencies").
- Flags `-root`/`-addr`/`-enterprise`/`-version`; same fail-closed bind guard
  (`:82-90`); single-project mode wires **outbound webhooks** from
  `KERN_WEBHOOKS` or `.kern/config.json` (`webhook.New()`, async goroutine, slow
  hook never blocks, `:99-127`); enterprise mode fails closed without
  `KERN_AUTH_TOKEN` (`:132-160`); graceful shutdown drain ≤10 s.

### `internal/web` — the console
- stdlib-only (ServeMux + `html/template` + `encoding/json`); read-only
  endpoints fail closed (500 JSON, never panic); write endpoints exist "for a
  loopback/local console … These are not an authentication boundary"
  (`web.go:11`).
- **Platform built once** in `web.New` (`web.go:254`, `app.NewWithGraph`); index
  + graph built once at startup — never per request; `freshGraph` rebuilds on
  staleness with stale-while-revalidate single-flight (`web.go:613`).
- 17 embedded HTML templates (`loadTemplates`, `web.go:345`; the embed
  directive at `dashboard.go:10`): dashboard,
  task_detail, agents, tasks, approvals, org_approvals, risks, artifacts, audit,
  system_map, incidents, efficiency, graph, memory, architecture, eval,
  benchmarks.
- Routes (`registerRoutes`, `web.go:453-523`): `/api/*` (overview, graph, memory,
  incidents, architecture, governance, performance, runtime, approvals, health,
  risks, artifacts, audit, system-map, efficiency); `/v1/*` (analyze, plan,
  what-if, impact, verify, memory, graph/, context, risk, agents, loop,
  incidents, correlate, learn, modernize, execute, audit/, tasks, tools/,
  artifacts, approvals, events/stream); HTML pages (`/`, `/task/`, `/agents`, …).
- **Auth:** `KERN_AUTH_TOKEN` opt-in bearer gate, constant-time compare
  (`authorized`, `web.go:574`); 1 MB `MaxBytesReader` on POST/PUT/PATCH
  (`:529-533`); per-IP rate limiter on mutating methods (`ratelimit.go`,
  `KERN_WEB_RATE_LIMIT`, default 600/min); CSRF/DNS-rebinding guard
  (`csrf.go`, `KERN_WEB_ALLOWED_HOSTS`).
- **`/v1/tools/{name}` passthrough** (`api.go:1183-1219`): POST-only → `a.tools.
  CallToolGoverned` (governed dispatch: KERN_TOOLS allowlist, root confinement,
  RBAC), 30-min timeout; unknown tool → 404, denied → 403; 503 when no factory.
  `/v1/events/stream` (`:1228`) is a JSON-lines SSE stream.

### Adjacent packages
- `internal/cockpit` — interactive terminal UI + triage runners (hosts `kern ops`).
- `internal/twin` — non-code dimensions of the Digital Twin (APIs, databases,
  messaging, infrastructure, runtime) + `Merge` with the code graph.
- `internal/webhook` — eventbus → outbound HTTP POST; SSRF-defensive; a dead URL
  never crashes the caller.
- `internal/eventbus` — deterministic in-process pub/sub, stdlib-only, no network
  I/O.

## 7. First-hour runtime (onboard / doctor / index / locks)

- **`kern onboard`** (`cmd_setup.go:212`): registers the repo in the repo
  registry (`intel.LoadRepos()`), builds/refreshes the index ("N symbols, N call
  edges, N files"), and wires AGENTS.md **only if missing** — "project-scoped:
  never touch user-global config" (`:260-275`). It does NOT write `.mcp.json`
  (that is `runSetup`'s job). Fails closed (exit 1) with: *"onboard: one or more
  steps failed — run `kern doctor` to diagnose, or `kern index` to rebuild the
  index"* (`:301-304`).
- **`kern doctor`** (`cmd_context.go:275` + `internal/doctor/doctor.go:42-65`):
  ~20 checks — binary, version, parity, capabilities, path (kern-mcp on PATH),
  binary-exec (actually probes the MCP initialize handshake), network-isolation,
  env, config, cache, sandboxes, wiring, plugin-sync, git-exclude, index,
  index-freshness, index-shadow, precision, runtime, ollama, stats. Any
  fail-level finding → exit 1 (CI-gateable); warn-only → 0.
- **`kern index`** (`cmd_index.go:190`): subcommands `ensure-fresh` (probe +
  rebuild + re-verify in one subprocess), `where`, `--status` (read-only health),
  `--update` (incremental), plain full rebuild. **On-disk artifacts under
  `.kern/`:** `index.json` (canonical JSON, `engine.go:184`), `index.sqlite`
  (SQLite-primary, WAL, `sqlite_store.go:50`; JSON is the fallback),
  `index.json.snap` (gob binary snapshot, ~5-10× faster decode, non-fatal,
  `snapcache.go:68-71`), workspace locks in `.kern/locks/`. First-run failure:
  `fatal("Index: %v", err)` (`cmd_index.go:314`); freshness skip prints "index:
  FRESH … use `kern index --force` to rebuild" (`cmd_index.go:307`). `kern bench`
  writes `.kern/bench.json`.
- **Locks:** `internal/flock` — the single cross-process flock(2) primitive; all
  four lock sites delegate (governance audit store, blueprint audit writer,
  JSON-file cache stores, workspace coordination). `internal/lock` — advisory
  workspace locks in `.kern/locks/` (OS-native flock / Windows exclusive-create,
  auto-released on exit, `ErrLocked` when held, holder PID + acquired time). CLI
  category: `lock`/`unlock`/`events`/`status`/`stream` (`dispatch_table.go:
  716-878`), publishing acquired/contended/released events through the relay.

## 8. Configuration surface

- **3-tier precedence** (`internal/config/config.go:1-17`, `resolve :123-144`):
  **env var > `.kern/config.json` (per project root) > built-in default**. An
  unset/empty/invalid env falls through to the file; absent/wrong-typed file key
  falls to default; malformed file prints one warning, never a hard error.
- **Secrets and safety toggles are intentionally env-only** (NOT in the file
  schema): `KERN_AUTH_TOKEN`, `KERN_GITHUB_TOKEN`, `KERN_K8S_TOKEN`,
  `KERN_ALLOW_*`, `KERN_TOOLS`, `KERN_MCP_*`.
- **Registry** (`config.go:455-490`, printed by `kern config`): `llm.provider`
  (ollama), `llm.model` (llama3.2), `llm.embed_model` (nomic-embed-text),
  `tokenizer`, `cost_per_token`, `cache.archive_days` (7) / `ttl_days` (30) /
  `max_mb` (1024), `runtime.poll_interval` (30 s) / `prometheus_url` / `otel_url` /
  `k8s.*`, `deploy.command` / `timeout` (5 m), `exec.risk` (MEDIUM), `mcp.roots`,
  `webhooks`, `enterprise.projects`.
- Notable env-only `KERN_*` vars: `KERN_ADDR`, `KERN_WEB_RATE_LIMIT`,
  `KERN_WEB_ALLOWED_HOSTS`, `KERN_MCP_FULL/PHASE/SINGLE_TOOL/HIGH_LEVEL_ONLY/
  PERMISSIVE/NO_CONFINE`, `KERN_ALLOW_EXEC/ALLOW_UNISOLATED/ALLOW_NET/

- `.kern/kern.yaml` — optional per-project log-compression profiles
  (exclude_patterns + truncate_rules), same graceful-degradation contract

- `docs/configuration.md`: zero-config by default; optional `.kern/boundaries.json`
  (architecture guardrails), doc-search index (Ollama-embedded), `.kern/agents.json`
  (custom agent wiring), `.kern/config.json`, `.kern/kern.yaml`; the secrets/safety

## 9. Benchmark methodology (what the docs actually promise)

- `docs/benchmarks/README.md`: "deterministic, stdlib-only, zero network, no LLM"
  suites, each answering one marketing claim with a machine-checkable protocol:
  semantic-retention (context efficiency, marker-retention ≥0.95 gate),
  graph-latency (cold/warm index + query latency), cold-start (one-shot cold
  build vs `grep -rn` across 83→7,819 files), telemetry-audit (CI-enforced
  zero-network-egress static import scan), token-savings (compact vs naive
  full-file), duplication.
- `docs/duplication-benchmark.md`: AST duplication scanner (`internal/scanners/
  duplication`) vs `jscpd` token matching on a calibrated fixture corpus;
  confusion matrix documented — advisory threshold 0.60 (FPR 0.75 → must stay
  advisory-only) vs calibrated 0.95 + AST-node size filter (FPR 0.00); two-pass
  blocking path (AST candidate >0.90 + `BlockEligible`, then independent `jscpd`
  confirmation to escalate to `duplication:confirmed-block`).
- `evaluate/README.md`: "the honesty bar" (credits code-review-graph's published
  36–376× benchmarks); fixed string corpora (no network, byte-for-byte
  reproducible); self-imposed honesty rules — token reduction vs the input given
  (never LOC→LLM-input ratios), line-structured inputs only, gates are
  regression tripwires not marketing targets; exit 0 only when every hard gate
  passes.

## 10. Fresh-eyes observations

1. **One binary, three binaries, two servers.** The "self-contained CLI" story
   is really a CLI + an MCP server + a stdlib-only web server, plus an in-process
   `kern serve` that injects the MCP factory to avoid an import cycle — the
   packaging has more surface than the tagline implies.
2. **139 tools / 200 commands, mostly deterministic.** The MCP catalog (139) and
   CLI table (216 entries, 200 non-alias) are huge for a "local engine"; the
   meta router and unified flag parser exist precisely to keep that surface
   navigable.
3. **Enforcement, not just guidance.** kern doesn't only *tell* agents to use
   `kern_*` tools — it installs PreToolUse hooks that *block* built-ins (exit 2)
   on 8 platforms and shadows read/grep/bash inside opencode, with explicit
   bypass env vars as the escape hatch.
4. **Confinement is layered and default-on.** Root confinement (4 layers) +
   `KERN_MCP_ROOTS` gate + `CheckExec` allowlist + web fail-closed bind guard +
   env-only secrets — the security posture is consistently fail-closed.
5. **The ledger is part of the build.** `ARCHITECTURE.md` LOC caps and
   `ledger-details.md` allowed-deps are enforced by a parity test (the
   enforcement contract is stated in the file's own header, `ARCHITECTURE.md:4`)
   — the architecture document is CI, not prose.
6. **Minor doc drift found:** embedded `global-rules.md` still claims "140
   tools" while AGENTS.md, the catalog, and live output all say 139.
7. **Unusual in-tree artifact:** a committed 54 MB `kern` binary sits at the
   repo root — a fresh dev might mistake it for a build output.
